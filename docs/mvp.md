# MVP

Текущая цель проекта — минимальная рабочая версия, на которой проверяем основную идею: **текст → эмбеддинг → поиск самого похожего фото** среди уже известного набора эмбеддингов (поиск по примеру изображения и пайплайн индексации — позже).

Полное видение — в [goal.md](goal.md).

## Что входит в MVP

### ML-модуль эмбеддингов

- Одна мультимодальная модель (CLIP): общее векторное пространство для текста и изображений.
- Интерфейс `EmbeddingModel`: `encode_text(text)` и `encode_image(image)`.
- Реализация на базе CLIP (например, `openai/clip-vit-base-patch32` или аналог через `transformers`).
- В MVP-потоках используется `encode_text`; `encode_image` — задел под индексацию и поиск по фото.

### Сервис поиска

- Поиск пути к **самому похожему** фото по текстовому эмбеддингу (косинусное сходство).
- Вход: текст → эмбеддинг → сравнение с заранее подготовленным набором `(путь, эмбеддинг фото)`.
- Для проверки MVP достаточно небольшого тестового набора в памяти (фикстура, ручная подготовка) — без отдельного пайплайна индексации.

### Точки входа

- **API (FastAPI)** — основной способ работы в MVP; вся функциональность доступна через эндпоинты.
- **CLI** — тонкая обёртка поверх API только для отладки (HTTP-запросы к локальному сервису, без дублирования бизнес-логики).

### API (FastAPI)

- Эндпоинт поиска: текст → эмбеддинг → путь к самому похожему фото.
- `GET /health` — проверка, что сервис жив и модель загружена.

### Конфигурация

- Запуск и использование MVP — через поднятый API-сервис (эндпоинты как главные точки входа).
- Имя/путь модели, host/port API для CLI-отладки.

## Что не входит в MVP

- Индексация каталога: сканирование папки, пакетный embed фото, сохранение индекса (позже — через отдельную библиотеку, не самописный JSON/pickle).
- Поиск по примеру изображения (image → embed → похожие фото).
- Видео.
- Распознавание лиц, детекция объектов, описание сцен.
- Векторные БД и search-либы для персистентного индекса (Qdrant, FAISS, Chroma и т.п.).
- Очереди, фоновые воркеры, watch на файловую систему.
- Авторизация, мультипользовательский режим.
- Кеширование запросов.
- Docker / docker-compose.
- Web-UI (достаточно Swagger FastAPI).

## Критерии готовности

- [ ] CLIP-кодировщик: текст и изображение дают эмбеддинги одной размерности.
- [ ] Сервис поиска на тестовом наборе `(путь, эмбеддинг)` возвращает корректный самый похожий путь.
- [ ] Поиск по тексту через API (например, «кот на диване») возвращает путь к самому похожему фото.
- [ ] `GET /health` отвечает успешно при поднятом сервисе.
- [ ] CLI-скрипт для отладки дергает те же эндпоинты, что и Swagger.

## Открытые вопросы

- Какую именно CLIP-модель брать (размер, скорость vs качество)?
- Как подготовить тестовый набор эмбеддингов для MVP (фикстура в репо, одноразовый prep-скрипт)?
- Какую библиотеку взять для индексации после MVP (FAISS, Chroma, Qdrant, …)?
